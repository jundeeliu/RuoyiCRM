# Eleven direct synthetic write candidates

[`direct-write-fixtures-candidates.json`](direct-write-fixtures-candidates.json) contains bounded JSON request bodies for the 11 `DIRECT_SYNTHETIC` source-bound cases. The run nonce is unique to this candidate set and every request is single-use on two fresh disposable stacks. These are **offline candidates**, not replay fixtures: `execution_status=NOT_RUN`, `baseline_oracles_captured=0`, `prewrite_snapshot.status=NOT_CAPTURED`, and `write_isolation=NOT_AUTHORIZED`.

Nine bodies have concrete synthetic values. Department creation still needs the ID of an active synthetic parent because `SysDeptServiceImpl.insertDept` dereferences the parent row; its `parentId` is explicitly `$REF:synthetic_active_dept_id`. User creation requires a disposable password supplied from private environment variable `CRIT04_SYNTHETIC_USER_PASSWORD`; no password is stored in the repository. Dictionary data has a concrete `dictType` matching the dictionary type candidate but requires that type to be created first, so case 041 must precede 035. All 11 require a tenant-scoped synthetic admin token, a source/target pre-case snapshot, a passing live dual-run write fence, and a captured baseline status/body oracle before replay. None of those conditions is assumed from this file.

When fresh stacks become available, materialize references only in a private temporary fixture file, capture MySQL and Redis snapshots separately for **each case**, validate `scripts.dualrun.fence.authorize_write` immediately before the HTTP operation, capture the baseline response and side-effect state, then compare the target response and state. Do not replay against the GET expansion stacks while they are in use. Any partial result requires quarantine and restoring or destroying **both** disposable stacks. Restoring a snapshot must be tested before it is trusted; deleting rows by a business predicate is not an adequate compensation mechanism because audit, cache, and related records may remain.

No baseline oracle has been captured for these candidates. The current `scripts/crit04_replay.py` can send non-GET requests when `--allow-writes` is supplied, but it does not itself enforce this candidate file's snapshot/fence contract. Do not pass that flag until the enforcement is integrated and reviewed.
